## Method and limits

- EXPLAIN ANALYZE on SereneDB 26.10.1 prints HTTP statistics (bytes in, GET and HEAD requests) and "Data Read" for remote Parquet, so bytes are measured per statement. docs/decisions.md said it reports rows and time but not bytes; that no longer holds for remote reads.
- SereneDB caches remote file data in memory (`enable_external_file_cache`). A first read fetches from S3 (cold); a repeat finds the bytes in the cache (warm, 0 bytes in). The cache is lost when the server restarts (it restarted after crashes during this work), while an agent index persists, so the cold column is what an agent pays on a fresh slice or after a restart.
- The shared dev server is reached through an SSH tunnel and fetches the file from S3 itself; other agents used it at the same time. Server times exclude the tunnel; tool times include it.
- The text_bench view casts the OTel Timestamp to TIMESTAMP, which keeps Parquet row-group pruning (timezone('UTC', ...) defeats it: a 1 s slice scanned all row groups) and depends on the session time zone being UTC, which `make huge-setup` checks.
- An index over a view of remote files is a snapshot taken at CREATE INDEX time; REINDEX INDEX refreshes it. The file is a published benchmark file, so the snapshot matches it.
- Runs per measurement: 3; medians are reported, every run is listed.
