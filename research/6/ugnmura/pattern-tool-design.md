# Independent parser implications for issue #2 (Codex)

These are interface recommendations, not executed database queries. Parser measurements live in `results/`.

`top_patterns` should aggregate matching **Log Entries**, partitioning pattern identity by Dataset and Component. Return a stable `template_id`, its `parser_version`/catalogue checksum, the exact `template_text`, `assignment_method` (`catalog`, `reviewed_mask`, `discovery`, `unmatched`, `ambiguous`), counts, count share with denominator, first/last timestamp, Components/Teams, and time buckets with an explicit interval and empty buckets. Always carry Evidence Ledger fields and list whether the response is top-N truncated. Do not call template counts incident counts.

The filter scope needs Dataset(s), start inclusive/end exclusive timestamps, optional Component(s), Team(s), levels and search criteria; use one common scope for total-match denominator, top-pattern counts and trends. Include `total_matching_entries`, `assigned_entries`, `unmatched_entries`, `ambiguous_entries`, `header_unparsed_entries`, `null_timestamp_entries`, returned group count and total group count. Diagnostic categories overlap (a line can have an unparsed header and be unmatched), so distinguish partition totals from auxiliary flags. Return `other_pattern_entries` for top-N remainder. An error-only question needs an explicit error-level/label/text predicate: the most frequent patterns are often ordinary work.

Stable key proposal: full SHA-256 of UTF-8 canonical JSON `[dataset, component, parser_version, template_text]`. Catalogue EventId alone is unsafe (E1 exists in multiple Datasets and catalogue revisions). Freeze templates before assigning final ids. Drain's sequential cluster id depends on input order, and its template text changes during training; neither alone is a durable cross-run identity. Store old->new mappings for deliberate catalogue migrations; never silently rewrite historical pattern identity. Using the full hash avoids needing an invented collision guarantee for truncated ids.

Add a post-loader enrichment sidecar keyed to the official loader's primary key. Proposed logical fields (types wait for official schema): `log_entry_id`, `dataset`, `component`, `parser_version`, `template_id nullable`, `template_text`, `assignment_method`, `candidate_count`, `header_status`. A template dictionary stores text once. Raw Log Entries remain available for Engineer retrieval. If the official loader lacks a stable key, settle one from source name plus source line number before enrichment; no row-number join to Loghub annotations.

Unmatched lines stay queryable and counted in a visible `UNMATCHED` partition. A masked fallback is a **candidate** pattern with separate provenance, never silently a curated template. Multiple catalogue matches are `AMBIGUOUS` until a reviewed specificity rule or reviewed exclusion resolves them. To drill down, offer bounded example `log_entry_id`s from the beginning/end of a pattern's time span plus ordinary pagination; keep the full raw line out of large aggregation results. Use `get_nearby` against original identifiers to inspect traceback context.

For unseen OTel data, do not claim BGL/OpenStack catalogue coverage. Route by source/service Component, freeze known templates, send unmatched messages to a separate Drain3 discovery queue and expose `new_candidate_pattern_count`, first seen, and sample ids. Promoting a discovery template requires a versioned artefact and regression comparison. Keep method/provenance visible when grouping mixed sources.

Measured trigger: full OpenStack catalogue uniquely matched 207,632/207,820 raw lines (99.9095%), with188 unmatched. Drain3 assigned100% but collapsed distinct VM lifecycle words and spawn/destroy words. Therefore assignment coverage must never be advertised as semantic accuracy, and a top-pattern response must surface parse-method quality limits alongside exact count arithmetic.
